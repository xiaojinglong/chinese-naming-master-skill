# 算法总览与数据流

> 描述取名 Skill 从"收集用户信息"到"输出报告"的完整数据流与模块依赖，便于实现时对号入座。

## 一、整体流水线

```
用户信息收集（04-输出与交互资料/01-用户信息收集模板.md）
      │
      ▼
① 八字排盘 ──► ② 五行分析 ──► ③ 喜用神
（01 规则）     （02 规则）        │
                                   ▼
④ 候选字生成（字库 × 姓氏 × 生肖喜忌 × 风格 × 文学素材）
      │
      ▼
⑤ 硬过滤（谐音/忌用字/严重克泄喜用）
      │
      ▼
⑥ 多维评分（五行/三才/五格/音韵/字形/寓意/生肖）
      │
      ▼
⑦ 排序输出 Top N + 报告生成（04-输出与交互资料/02-输出报告模板.md）
```

## 二、数据流明细

| 步骤 | 输入 | 使用的资料 | 输出 |
|---|---|---|---|
| 1. 排盘 | 公历年月日时 | 01-八字排盘规则 + lunar-python 等库 + tiangan/dizhi | 四柱八字 |
| 2. 五行分析 | 四柱 | dizhi.json（藏干）、02-五行分析规则 | 五行分布、日主强弱 |
| 3. 喜用神 | 五行分布+强弱 | 02-五行分析规则 | 喜用五行/忌神五行 |
| 4. 候选生成 | 姓氏+喜用+风格 | 姓氏库、汉字字库、文学素材库、生肖喜忌 | 候选名集合 |
| 5. 硬过滤 | 候选名 | 谐音黑名单词库（04-谐音黑名单词库.json）、用户忌用字、五行规则 | 过滤后候选 |
| 6. 评分 | 过滤后候选 | 评分规则 + 三才表 + 数理表 + 权重配置 | 各维度得分 |
| 7. 报告 | 得分明细 | 输出报告模板 | 最终报告 |

## 四、状态与边界处理

1. **出生时间缺失**：跳过排盘，走"生肖+字义+音韵+五格"简化模式，报告标注"未排八字"。
2. **时辰缺失**：用日柱+默认时辰（子时）排盘，报告标注"时辰为默认假设"。
3. **姓氏不在库**：提示用户输入繁体笔画，或按简体笔画近似 + 提示。
4. **名用字不在字库**：按"部首+常用音"推断五行并标注置信度；建议用户确认。
5. **性别**：影响候选字性别倾向（字库可加 gender_hint 字段），不强制。
6. **风格偏好**：映射到候选字来源（文学素材库筛选）与权重预设（06-评分权重配置.json）。

## 五、质量保障

- 每个输出名字必须有完整的"推理链"（为什么选、五行如何、五格多少、寓意出处），报告模板强制输出。
- 所有传统判定（三才/数理/生肖）注明"民俗参考，非科学验证"，避免误导。
- 数据与代码分离：规则文档只描述逻辑，实际判定以 JSON 数据 + 代码实现为准。

# 交互流程设计

> 描述取名 Skill 与用户的多轮交互流程（从发起请求到交付报告的完整 UX 设计）。

## 一、流程总览

```
用户发起（"帮我给宝宝取名字"）
   │
   ▼
[第1轮] 收集信息（01-用户信息收集模板.md）
   │  └─ 缺省字段 → 降级模式
   ▼
[处理] 排盘 → 五行 → 候选 → 过滤 → 评分（算法总览与数据流.md）
   │
   ▼
[第2轮] 呈现 Top 3 简版卡片（名字 + 评分 + 一句话寓意 + 关键提示）
   │
   ▼
[第3轮+] 用户反馈循环：
   │   ├─ 喜欢某名 → 生成完整报告（02-输出报告模板.md）
   │   ├─ "换一批" → 更换候选来源/权重重新生成
   │   ├─ "偏男性/偏女性" → 调整性别倾向重排
   │   ├─ "不要太传统" → 调权重预设（现代好听）
   │   └─ "再详细点" → 直接给完整报告
   ▼
[收尾] 完整报告交付 + 收藏/分享建议
```

## 二、每轮的关键设计

### 第 1 轮：采集
- **原则**：一次一问，最多问 7 项；用户不耐烦时接受最小输入（姓氏+性别）。
- **技巧**：把"出生信息"解释为"不记得也没关系，可以提供大致年月"，降低门槛。
- **校验**：姓氏查库、日期合法性、忌用字去重。

### 第 2 轮：简版呈现
- 每名一行卡片：`名字（评分）—— 一句话寓意`
- 高亮最佳名；标注每个名字的"最大亮点"（如"五行补益最强""寓意出自诗经"）。
- 底部引导："回复数字查看完整分析，或说'换一批'。"

### 第 3 轮：反馈循环
- **重生成策略**：
  - 换一批 → 换候选池（文学素材换库/换意象主题）+ 扰动排序。
  - 调风格 → 换权重预设（06-评分权重配置.json）。
  - 调性别 → 加性别过滤重排。
- **防重复**：维护已推荐名单，重生成时排除。

### 收尾：完整报告
- 交付 Markdown/HTML 报告（结构见 02-输出报告模板.md）。
- 报告含全部候选（Top 5-10）完整卡片 + 口径附注。

## 三、异常与边界交互

| 场景 | 处理 |
|---|---|
| 用户只给姓氏 | 降级模式 + 提示补充出生信息可获得更准推荐 |
| 姓氏查不到 | 请用户提供繁体字形与笔画（或按部首近似） |
| 用户对结果不满（多次换批） | 主动询问核心诉求（八字/好听/寓意）并调整权重 |
| 用户问"哪个最好" | 推荐综合分第一，但说明"最终以个人喜好为准" |
| 用户要"生辰八字详解" | 输出排盘摘要（四柱/五行分布/喜用神），不越界预测命运 |

## 四、合规与体验红线

1. 不承诺"改名转运""包生男"等虚假功效。
2. 涉及"命运/婚姻/健康"等表述一律弱化或省略。
3. 未成年人取名场景：仅服务"家长为子女取名"，不收集无关隐私。
4. 用户明确表示"不要太迷信"时：自动关闭传统维度（三才/数理/生肖），只保留字义+音韵+字形+五行补益。

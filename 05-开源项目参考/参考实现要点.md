# 参考实现要点

> 从五个开源项目中提炼的**可复用实现要点**，按功能模块组织，开发 Skill 时直接对号入座。

## 一、数据层（参考 James88/qiming、baobao-qiming）

1. **字库三件套**：拼音+偏旁（xinhua.csv）｜五行繁体字典（wuxing_dict_fanti.json）｜全量汉字（word.json）。
2. **加载策略**：
   - 全量库（27000+）用 JSON/CSV 按需加载，或转 SQLite 索引。
   - 前端/插件场景用压缩后的常用字子集（如 baobao-qiming 的做法，几百字即可跑通）。
3. **康熙笔画**是五格计算的唯一口径，务必单独维护（简体笔画不可混用）。
4. **五行字段双口径**：`wuxing`（主要）+ `wuxing_basis`（口径标记：字义/字形/笔画），解决流派冲突。

## 二、排盘层（参考 chinese-name-craft、baobao-qiming）

1. **不手写天文算法**：直接用 lunar-python / sxtwl / cnlunar（节气、四柱、生肖一步到位）。
2. **边界必测用例**：
   - 立春前后 1 分钟（年柱切换）；
   - 节气交接时刻（月柱切换，如立秋当天 00:00 与 23:59）；
   - 23:00 前后（日柱切换，子时换日）；
   - 闰月出生（农历闰月映射到节气月）。
3. **时辰缺失默认值**：统一默认子时，并在报告标注，避免用户误解为精确排盘。

## 三、五行与喜用神层

1. **强弱判断用四维打分**（得令/得地/得势/得助），不要只看"缺不缺"。
2. **喜用神输出为"五行集合+优先级"**（如喜木火，忌金），供评分模块直接消费。
3. **调候**作为可开关的附加规则（寒暖局），默认开启、低权重。

## 四、五格三才层

1. **计算与查表分离**：
   - 计算：五格笔画（纯函数，输入：姓名+康熙笔画）；
   - 查表：三才 125 / 数理 81 均为静态 JSON（本库已提供）。
2. **版本标注**：三才/数理表都写明"版本口径"，便于将来换表。

## 五、音韵层

1. 拼音数据要**带声调**（本库 pinyin 字段已带）。
2. 声母/韵母/声调拆分写纯函数（输入拼音字符串，输出三段）。
3. **谐音黑名单可持续扩充**：核心是"姓氏×名"组合风险表（如吴+德），比单字表更实用。

## 六、生成与评分层

1. **候选生成三步**：
   - 字源池：字库（五行过滤）∪ 文学素材（风格过滤）∪ 生肖喜忌（偏旁过滤）；
   - 组合：姓 × 候选字（两字名/三字名分别枚举，控制组合规模）；
   - 过滤：硬过滤（谐音/忌用字/克泄喜用）→ 评分 → 排序。
2. **评分模块化**：七个评分函数各输出 0-100 + 说明，权重从 JSON 读（06-评分权重配置.json）。
3. **组合爆炸控制**：候选字池建议每维度先 top-K 截断（如五行合 50 字、音韵优 30 字），再交叉，避免指数级枚举。

## 七、交互与输出层

1. 采集用"对话式渐进收集"，提供降级模式（姓氏+性别即可）。
2. 简版卡片 → 反馈循环 → 完整报告，三级交付（见 `04-输出与交互资料/交互流程设计.md`）。
3. 报告结构用 JSON Schema 约束（`02-output-report-schema.json`），渲染层只管展示。
4. 所有传统判定输出带"参考"措辞 + 数据来源，报告附口径说明。

## 八、工程建议

| 关注点 | 建议 |
|---|---|
| 依赖 | 历法库（lunar-python）+ 谐音词库（开源）+ 通用规范汉字表 |
| 测试 | 边界用例集（立春/节气/子时/闰月）+ 常见姓名黄金样例（如"李明"五格=8/15/9/2/15） |
| 性能 | 字库转 SQLite/索引；候选生成限制规模 |
| 可维护 | 数据与代码分离；规则文档（本库）与实现一一对应 |
